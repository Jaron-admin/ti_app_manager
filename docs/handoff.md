## 项目

Ti 软件管家：Windows 桌面端，把「已安装 / 装 / 更新 / 卸载」收进一个界面。
数据与执行都委托给本机已有的轮子——清单、搜索、安装、更新、卸载走 `winget`，深度清理走本机已安装的
BCUninstaller（未安装则该选项灰显）。程序自身不分发任何第三方可执行文件，也不上传任何信息。

首版按便携 zip 交付，不签名，给本人和朋友用。

## 工具链（按项目锁定的版本，新机先核对再决定装不装）

- Flutter 3.41.9 / Dart 3.11.5（`pubspec.yaml` 约束 `sdk: ^3.11.5`）；仅 `windows` 平台，仓库里没有 `macos/` runner。

## 第 8 步待办（都需要本人点头，不是代码问题）

1. 挑一个确实不要的软件，真机跑一次完整卸载（winget 引擎与自带卸载器引擎各一次）。
2. 安装 BCUninstaller，走一次深度清理。
3. 切系统主题，核对深色下的标题栏与令牌一致性。
4. 定许可证：规约默认新建原创项目用 `GPL-3.0-only`，尚未落文件；影响将来对外分发包时的源码义务。

## 隐私红线

- `test/fixtures/*.txt` 是**本机真实 winget 输出**截取的片段，会暴露装了哪些软件。仓库若转公开，必须先换成脱敏夹具；测试只依赖表格列位与字符宽度，不依赖具体软件名。
- 设备路径、代理、SDK 位置、技能链接等本机事实不进仓库，只写各机自己的 `Agents_Local.md`。
- 构建产物不进源码仓库，放 `<ARTIFACTS>/<project>/`。

## 新设备接续

1. 取当前开发分支（远端地址与分支名见交接回执，不写死在本文件）。
2. 按规约 §1.1 解析新机 `<SDK>` `<PROJ>` `<CACHE>` `<ARTIFACTS>`，输出 `[env]` 回执；新机没有 `Agents_Local.md` 就先按规约生成。
3. 用新机的 `<SDK>` 内 Flutter 跑 `flutter pub get`（镜像与 pub 缓存变量按新机 `Agents_Local.md`，缺了会静默挂住），再 `flutter test` + `flutter analyze`。
4. 在新机 Windows 上 `flutter run -d windows`，确认能读到自己的 winget 清单——首次 `winget list` 约 20 秒，程序会先显示上次缓存的清单并标注时间。
5. 从上面「第 8 步待办」的第一项继续；编译通过、程序启动、本人验收是三件事，分别报告。
